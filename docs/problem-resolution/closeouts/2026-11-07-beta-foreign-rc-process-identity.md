# Problem-resolution closeout

Issue: 2026-11-07/08 · Beta deploy preflight must recognize a foreign RC JVM with absent or stale Beta marker
Date: 2026-11-08
Status: OPEN — focused source/test verification passed; the secretary owns deployment and live correlation.

Investigation and cause: PASS — The original 2026-11-07 preflight saw Java PID 44880 with blank command line and no Beta marker; its exact window title `HS Script Release Candidate` proved it was a foreign RC process. Commit `b63bdd4e` added a precise foreign-window exclusion but called it only when the Beta marker file was absent. On 2026-11-08 the same exact RC JVM was visible while Beta retained a structurally valid but stale marker whose PID was absent. The early scan skipped title classification because a marker file existed, then the final scan rejected PID 44880 as unidentified. The repeated deployment refusal was therefore caused by marker-file presence suppressing the already established foreign-window check, not by uncertainty in the observed RC identity.

Fix: PASS — `Stop-ManagedHsScriptProcesses` now checks the exact window title for each command-line-hidden Java process regardless of Beta marker-file presence. Only an exact `HS Script Release Candidate` title gets the foreign exclusion. A stale Beta marker remains unchanged and its absent PID is ignored only through the existing process-snapshot check. Exact Beta marker PID/start-time/executable/manifest verification remains separate; unknown or altered titles still fail closed. `RELEASE-CHANNELS.md` now states the marker-independent foreign classification and preserves marker identity as the only Beta stop authority. Deployment SOP read — reviewed `docs/OPERATIONS-SOP.md`, `docs/RELEASE-CHANNELS.md`, and the canonical 2026-11-07 foreign-RC closeout before editing; the existing process identity rule is extended in place rather than duplicated.

Verification: PARTIAL — `tests/BetaDeploymentProcessStop.Tests.ps1` passes cases for exact RC window classification with no marker and with a stale valid Beta marker, unknown-title refusal in both conditions, unchanged marker bytes, no stop request for the RC JVM, and exact Beta marker ownership. The closeout validator and its regression suite pass. No deployment, runtime, manifest, launcher, shortcut, process, or game was modified or stopped; live deployment correlation remains with the secretary.

Future prevention: PASS — Classify a foreign process from its exact process-bound identity independently of stale metadata-file presence, but keep foreign exclusion separate from channel ownership. Never use a window title to authorize a Beta stop or a broad unknown-Java ignore rule.

Prevention enforcement: PASS — test: `BetaDeploymentProcessStop.Tests.ps1` requires the exact RC title to be excluded with absent and stale valid Beta markers, rejects unknown titles in both cases, verifies the stale marker remains byte-identical and the stop callback is not called, and confirms exact Beta marker identity remains independently actionable.
