# Runtime and Interaction Runbook

This runbook documents the reliable way to operate this fork on Windows and the failure modes that are easy to misdiagnose.

## Startup order

1. Stop any previous script instance before starting another one. Use the script's Pause/Exit controls, its `Alt+P` stop shortcut, or the packaged `force-stop.exe`.
2. For a clean restart, close the Battle.net/Blizzard client first. Only close the Hearthstone game window when a full game restart is intended. Do not terminate unrelated processes merely because their names contain `Agent`.
3. Start the copy that is actually being tested from the updated Desktop or Start Menu shortcut. The shortcut invokes `launch-as-admin.vbs`, which uses Windows `runas` and should display a UAC prompt.
4. Approve the UAC prompt. The script and Hearthstone must run at compatible integrity levels or DLL injection can fail.
5. Wait until the script window is ready, then choose the game mode first, the strategy second, and the deck position third. For Wild, select `狂野模式`, verify the intended deck is in the configured deck slot, and only then click `开始`.

Do not start the JAR with an arbitrary `java`/`javaw` command. A non-elevated Java child process can make the UI appear to work while `inject-util.exe` fails later with Windows error 740.

## UI interaction rules

- Perform one UI action at a time and wait for the screen or log to change before sending the next action.
- Re-observe the current screen after mode changes, dialogs, game transitions, or any action that changes layout. Old coordinates and stale control references are unsafe to reuse.
- Do not repeatedly click `开始`, mode selectors, or `回合结束` while the previous action is still pending; this can create duplicate timers or race the game state.
- If the UI appears stuck, inspect the latest log before clicking again. A pause state is not the same as a crash.
- When a UAC prompt appears, it must be accepted by the user; it should not be automated or bypassed.

## `打一投一` behavior

`打一投一` is a control layer, not a replacement for the selected normal strategy:

- Game 1 uses the strategy selected in the normal strategy dropdown.
- Game 2 uses the loaded `秒投策略`.
- The pattern repeats for later games.
- If `秒投策略` is not loaded, the log reports a warning and the current strategy is used as a fallback.

Leave the normal strategy selected. Enable or disable the `打一投一` checkbox on the main window instead of manually changing the strategy after every game.

## Random timing behavior

The app and its strategy/card plugins share the same `RandomUtil` stream. A fresh seed is generated with `SecureRandom` when mode entry starts and again when matchmaking must be retried. The log records it as `本局共享随机种子：...`.

The seed is shared; the delay is not. Each delay consumes the next value from the shared stream, so repeated short pauses are not all the same number. The current helpers include:

- action intervals: configured center ± `max(100 ms, 10%)`;
- mulligan startup: 20 seconds ± 1 second, plus optional distortion of about 4.5 seconds ± 0.5 seconds;
- beginning of turn: 5 seconds ± 0.5 seconds;
- mode entry: 750–1,250 ms initial delay and 4,000–6,000 ms polling interval.

This means a log replay is not expected to have identical timings across runs, even when the same strategy is selected.

## Logs and crash triage

Collect these before restarting after an apparent disappearance:

- `log/hs_script.log`;
- the relevant rotated `log/hs_script-*.log` file;
- the Hearthstone `<game-root>\Logs` files;
- the selected mode, strategy, whether UAC was accepted, and the last visible UI state.

Useful indicators:

- `CreateProcess error=740` or `请求的操作需要提升` means the script was not elevated; restart through the administrator shortcut.
- `注入hs_base.dll异常` means to inspect elevation and the native helper files before changing strategy settings.
- A missing script window does not prove the process exited; the app can minimize to the tray or leave only a Java process. Check the process/log state before launching a second copy.

## Packaging gotchas

- `source/hs-script-app/src/main/resources/app.manifest` requests `requireAdministrator` for native builds.
- `launch-as-admin.vbs` and the self-elevating `hs-script.bat` are launch helpers; they are not substitutes for a correctly packaged EXE.
- Desktop/Start Menu shortcuts and the per-user `RUNASADMIN` compatibility entry are Windows-machine state, not portable source files. Recreate them when deploying to another Windows account or another package path.
- Keep the tested EXE, JAR, native helpers, plugins, and working directory from the same package. Mixing an old EXE with a new JAR or helper can reproduce failures that look like timing or strategy bugs.

## Lifecycle diagnostics and Wild E2E

The application writes `LIFECYCLE_EVENT`, `LIFECYCLE_STATE`, and `LIFECYCLE_HEARTBEAT` records to `log/hs_script.log`. These include the Java PID, pause/working state, main-window visibility, current mode, game phase, turn state, and completed-game count. A close-button request is logged as `close-request-consumed-hide`; it hides the main window and does not terminate the process. A real shutdown is logged separately by `shutdown-request` and `ShutdownTrace`.

The packaged `run-debug.cmd` invokes `run-debug.ps1`. It polls the Java PID, main-window handle/title, and the latest script-log line every five seconds, records premature process exits, and only succeeds after an `E2E_WIN_RESULT <run-id>` marker. The E2E launcher intentionally does not use the surrender-after-first-card shortcut, so a surrender or loss cannot be mistaken for a completed Wild-game test.

To run the test from the package directory, start `run-debug.cmd` while Hearthstone is already logged in. The test is allowed to restart the script after a premature exit, but it must not be used while another script instance is active. Preserve `log/java-console-debug.log`, `log/hs_script.log`, and the screenshot captured at the `E2E_WIN_RESULT` marker as the test evidence.

The administrator launch helper no longer passes `--pause=false` or `-Dhs.script.autostart=true`. The main UI has a separate `打开时自动开始` checkbox, disabled by default. E2E and other deliberate automation can still opt in with an explicit start parameter.

## Source-control scope

This is a multi-module superproject. The active localized-version work, timing changes, strategy alternation, UI changes, shared utilities, SDK/plugin changes, launcher files, and this documentation belong to the same development snapshot when they are part of the current test build.

The `source` directory contains Git submodules. Before publishing, inspect the superproject and every dirty submodule separately. Commit submodule changes in their own repositories first, then commit the updated submodule pointers and documentation in the superproject. Do not publish only the output package and call that a source backup.
